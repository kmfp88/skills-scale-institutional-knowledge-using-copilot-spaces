# OctoAcme Project Management Docs

This folder contains OctoAcme's project and program management guidance. It provides a central entry point for understanding how the team initiates, plans, delivers, releases, and improves work across projects.

## Brief summary of OctoAcme project management processes

OctoAcme follows a lightweight, customer-first project model designed to keep teams aligned while remaining flexible and delivery-focused. The process emphasizes clear ownership, visible progress, and continuous improvement.

- Initiation: Define the problem, stakeholders, success metrics, and business case before approving the work with a project one-pager.
- Planning: Prioritize the backlog, estimate scope, define Definition of Done, and align on milestones and release plans.
- Execution and tracking: Use a project board (Backlog → Ready → In Progress → In Review → QA → Done), keep PRs small, validate with CI checks, and hold regular team rhythms such as standups and delivery syncs.
- Release and deployment: Validate readiness with pre-release checks, automate deployment where possible, smoke test the release, and maintain a rollback path.
- Retrospective and continuous improvement: Review outcomes, capture learnings, track action items, and measure the effect of improvements over time.
- Risk and communication: Maintain a risk register, share status updates with stakeholders, and escalate blockers or incidents through the agreed communication path.
